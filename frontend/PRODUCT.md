# The Enforcer

<!-- impeccable:product-schema 1 -->

## Platform
web

## Users and purpose
Student project teams agree on a plan, deliver checkpoints, and coordinate when someone needs help. The app measures agreed requirements rather than commit activity or teammate rankings.

## Positioning
The plan is the referee. Progress means an agreed checkpoint's requirement is met, never commit activity and never a comparison between teammates. Reminders are private first: an agent checks the repo, privately nudges the owner of a missed checkpoint, and tells the team only after an agreed grace period. Every reminder can be answered (On it, Blocked, Need help), and Blocked pauses the grace clock and nudges the blocker instead. Whether to nudge is decided by plain rules; a model only writes the wording. It coordinates and never grades, ranks or scores contribution.

## Operating context
React/Vite web app, used on laptops and phones, with a desktop workspace and an installable mobile web experience. Existing routes: Setup, Task map, Dashboard, Inbox, Trace, Report. Public sample data and live signed-in projects are distinct modes.

## Capabilities and constraints
Preserve project setup, file upload, plan editing and approval, member selection and authentication, checkpoint status, owner-only evidence and disputes, reminder responses, trace/check-in/simulation controls, compute meter and report export. Preserve API contracts and privacy. Never invent progress, deadlines or capabilities. Repositories and README define the existing product behavior.

## Brand commitments
The mascot is The Enforcer; the user explicitly delegates his character design. He is serious but lovable, firm and friendly, observant and supportive. The identity is refined and charming, not babyish, goofy, toy-like, harsh, sterile or corporate-generic. Muted attractive accents, calm neutrals, strong hierarchy and restrained rounding. Character appearances support onboarding, empty/error/loading states, reminders and progress; he must not dominate every screen.

## Principles
- Accountability without humiliation or comparisons.
- Make the next useful action clear.
- Keep factual team progress separate from personal evidence.
- Keep real controls, accessible labels, focus, reduced-motion support and responsive layouts.
- Preserve the operating app while replacing its visual system.

## Evidence
Existing mock project and demo fixtures provide labeled sample content. No commercial claims, testimonials or new feature claims are supplied.
